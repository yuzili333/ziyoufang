# 字有方 MVP 业务需求说明书

## 1. 功能名称

汉字书写智能评测与矫正闭环（MVP）

## 2. 功能描述

### 2.1 业务背景

小学生需要通过反复书写掌握汉字的笔顺、结构、准确性和美观度。现有书写成果主要依赖人工点评，评价标准难以量化，学生也缺少可持续的自助练习与改进工具。

字有方 MVP 通过学生拍照上传/或选择相册中的练字成果，对汉字进行逐字识别、书写质量评价、错字与待纠偏字诊断，并提供手写字与标准宋体字形的差异对比。学生依据大模型对确定性证据的解释和纠偏建议继续练习；系统将问题字加入对应字本，记录同一问题字的历次结果和矫正进度。

### 2.2 MVP 目标

- 验证从练习上传到问题字识别、针对性矫正和历次结果对比的完整业务闭环。
- 验证自动识别、书写评价和问题解释是否能够帮助学生发现书写问题。
- 验证大模型纠偏建议是否清晰、可执行，并能够帮助学生自主完成纠偏和纠错。
- 沉淀问题字、练习记录、模型建议和学生反馈，为后续持续改进提供可追溯数据。
- 验证五维字形评价、成长曲线和重点字库能否帮助学生持续关注反复低分或表现不稳定的汉字。

### 2.3 MVP 范围

- 通过微信身份进入小程序，在首次图片处理前完成隐私授权和监护人确认。
- 提交包含一个或多个汉字的练习图片及目标练习内容。
- 检查图片是否具备可评测条件，并提供明确的失败反馈。
- 通过方格切分和 OCR 逐字识别学生书写内容，保留位置、候选和置信信息。
- 通过目标文字、重复 OCR 和结构证据形成错字或不确定结论。
- 参考版本固定且许可明确的标准宋体字形进行确定性差异计算和书写质量评价。
- 对每个可评价汉字提供笔画规范、间架结构、字形比例、位置布局和稳定性五个维度。
- 区分错字与待纠偏字，说明笔画、偏旁、部首或整体结构问题。
- 展示手写字、标准字形及差异信息。
- 在同一问题字本中维护错字和待纠偏字筛选。
- 记录同一问题字的重复练习和矫正状态。
- 同一目标字积累三次及以上有效、可比练习后展示成长曲线；将近三次均分或稳定性偏低的字纳入重点字库。
- 支持学生依据大模型对确定性证据的解释直接练习，并对明显错误的识别或评价结果提交反馈、触发重新评测。
- 支持监护人再次确认后生成不含原始练字照片的脱敏结果分享卡。

### 2.4 MVP 不包含

- 人工审核、班级、课程、作业布置、批量催交和教务管理。
- 独立统计与周期汇总能力。
- 原始练字照片分享、公开动态、排行榜、挑战、积分、勋章和付费能力。
- 标准字库制作、模型训练平台和人工标注平台。
- iOS、Android、HarmonyOS 独立安装包；MVP 以微信小程序作为客户端载体。
- PAD 专属交互、手写笔、键鼠快捷键和跨微信账号的数据同步。

### 2.5 MVP 成功判定

- 学生能够完成“提交—评测—查看问题—加入问题字本—再次练习—查看矫正进度”的完整流程。
- 学生能够理解大模型给出的书写问题与纠偏建议，并据此发起下一次针对性练习。
- 每个问题字均可追溯到原始练习、大模型建议、评测状态、学生反馈和历次矫正记录。
- 学生能够区分单次五维评分和跨练习稳定性；样本不足三次时不显示伪稳定性结论。
- 达到重点监测条件的字能够进入“我的—字本—重点字库”，并显示入库原因和成长曲线。
- 图片不可处理、识别不确定或评测失败时，不生成伪确定结论，并向用户提供可行动的处理建议。
- 识别、分类、评分和效率的量化验收指标待合法样本及评测基线建立后补充。

## 3. 相关用户

| 用户 | 参与方式 | MVP 职责 |
| --- | --- | --- |
| 学生 | 发起人、结果查看人、练习执行人 | 提交练习，查看评价与对比，针对问题字重复练习，查看单字矫正进度 |
| 监护人 | 授权与分享确认人 | 完成首次未成年人图片处理确认；在生成脱敏结果分享卡前再次确认 |
| 业务管理人员 | 待补充 | 是否需要管理标准字形、评价口径或用户关系尚未明确，不纳入 MVP 默认功能 |

## 4. 业务规则

### 4.1 提交练习

- 微信身份：学生从微信进入小程序；微信身份只用于当前产品的主体关联和访问控制，不自动等同于监护人法律身份。
- 监护人确认：首次处理练字图片前必须完成隐私告知和监护人确认；确认文案、适用年龄和撤回方式须经合规审批。
- 关联练习主体：每次练习必须关联唯一的学生或练习主体标识；无法确认练习主体时，不得写入个人字本或矫正记录。
- 提交练习材料：学生提交练习图片和目标练习内容；目标练习内容用于判断实际书写与预期汉字是否一致，缺失时只能形成识别建议，不能形成确定的错字结论。
- 记录练习批次：每次有效提交形成独立练习记录，并记录提交时间；重复上传是否合并待原型阶段确认，MVP 默认视为不同练习记录。
- 核验数据授权：练习图片涉及未成年人书写数据，未取得有效授权或授权状态不可确认时，应拒绝进入评测和持久化流程。

### 4.2 检查图片质量

- 检查可评测性：检查图片是否存在严重模糊、过暗、过曝、遮挡、裁切不完整或无法定位汉字等情况。
- 处理不合格图片：图片不具备评测条件时，终止本次评测，保留失败状态并说明重新拍摄或调整方式，不写入问题字本。
- 处理部分可用图片：图片中仅部分汉字可评测时，应明确区分成功、失败和不确定的单字；是否允许部分结果进入字本待原型评审确认，MVP 默认仅将达到有效结论条件的单字写入。

### 4.3 识别书写内容

- 切分书写汉字：根据练习图片和目标练习内容定位单个汉字；无法可靠切分时，将相关字符标记为待确认，不继续形成确定评价。
- 识别实际汉字：对每个可处理的手写字给出识别建议和不确定性信息；识别不确定时，应提示学生确认目标汉字或重新拍摄，不能将低可信建议作为最终事实。
- 对齐目标内容：将识别结果与目标练习内容逐字关联；数量不一致、顺序不一致或无法对齐时，应标记具体问题，并引导学生确认目标内容或重新提交。
- 二次识别：整页 OCR 低置信或与目标关系冲突的单格应进行二次识别；稳定单格不重复调用，以控制成本。
- 稳定错字：只有两次 OCR 均稳定识别为同一非目标字、且对齐关系明确时，才能形成确定错字结论；一次识别或模型自由文本不得单独判错。

### 4.4 评价书写质量

- 选择评价基线：按原始需求以标准宋体字形作为参考基线；具体字体文件、许可证、版本、规范笔顺及适用字集待补充。
- 生成质量评价：对可处理汉字形成 `0–100` 的总分和五维评分；权重、等级和生产阈值须经合法样本与汉字书写专家评价基线确认，并以评分版本固化。
- 笔画规范：评价静态图片中可见笔画的形态、方向、长短、衔接和缺失/多余情况；单张照片不能可靠判断实际书写笔顺，不得把笔顺作为已验证结论。
- 间架结构：评价部件、偏旁和主体之间的组织关系、疏密、对齐和结构重心。
- 字形比例：评价字的整体宽高、部件尺度和主要结构比例。
- 位置布局：评价字在田字格中的居中、占格、留白和上下左右位置。
- 稳定性：评价同一学生、同一目标字在最近三次可比练习中的波动和持续上升/下降趋势；绝对水平由最近三次均分独立表达，不足三次时返回空值并显示“样本积累中”。
- 提供可理解说明：评价应指出笔画、偏旁、部首或整体结构层面的主要问题，避免只提供无法指导练习的单一分数。
- 保留不确定性：证据不足时，评价状态应为待确认，不得以确定语气判定书写优劣。
- 固化评价证据：评分必须关联确定性特征、问题代码、评分版本和标准字形版本；模型建议不能覆盖上述结果。

### 4.5 识别问题字

- 判断错字：当实际书写与目标汉字在关键笔画、偏旁、部首或整体结构上不一致，并满足待补充的错字判定口径时，形成错字建议。
- 判断待纠偏字：当书写内容与目标汉字一致，但结构比例、笔画位置或整体形态未达到待补充的书写质量口径时，形成待纠偏建议。
- 处理问题并存：同一汉字同时满足错字和书写质量问题时，MVP 优先归为错字，同时保留纠偏问题说明，避免重复统计同一次练习。
- 处理正常汉字：未发现错字或明显书写质量问题时，标记为本次评测正常，不进入问题字本。

### 4.6 展示字形差异

- 形成差异对比：对错字和待纠偏字提供手写字、标准字形及差异信息，帮助学生定位主要书写问题。
- 对齐问题说明：差异信息必须与文字问题清单保持一致；无法建立可靠对应关系时，应说明限制，不展示可能误导学生的差异结论。
- 保留原始证据：差异对比应能够回溯至本次练习中的原始手写区域和采用的标准字形版本。

### 4.7 使用大模型纠偏建议

- 生成当前结果：OCR、目标文本对齐和版本化图像算法完成识别、分类与评价；满足有效条件的确定性结果作为本次当前结果，用于问题字本和矫正进度。
- 提供练习指导：对错字和待纠偏字给出与差异证据一致、学生可理解且可执行的纠偏或纠错建议，学生可依据建议发起下一次针对性练习。
- 限制模型职责：大模型只解释输入的 OCR 候选、确定性差异特征和问题代码，并生成最多三条练习步骤；不得修改识别字、分类、评分或证据。
- 控制调用范围：正常且高置信单格不调用大模型；问题字和不确定字可批量调用，每批最多八个单字。
- 模型降级：模型超时、限流、输出不符合 Schema 或服务不可用时，保留识别、评分和差异结果，改用规则模板建议，不让整次评测失败。
- 标识不确定结果：证据不足或置信度未达到待补充阈值时，将对应汉字标记为待确认，并提示学生确认目标内容、重新拍摄或重新提交；待确认结果不得写入问题字本或计入矫正进度。
- 接收学生反馈：学生认为识别、分类或评价存在明显错误时，可提交“结果有误”反馈；反馈不得直接篡改原结果，应触发重新评测并保留反馈原因和时间。
- 更新关联数据：重新评测形成新结果后，问题字本和矫正进度采用最新完成结果重新计算，同时保留原始结果和版本变化记录。

### 4.8 维护问题字本

- 写入错字本：完成评测且结果为错字时，将目标汉字、问题说明、原始练习和评测时间关联到错字记录。
- 写入待纠偏筛选：完成评测且结果为待纠偏、且未归为错字时，将对应内容关联到问题字本的待纠偏筛选。
- 合并同字记录：同一学生、同一目标汉字的多次问题记录归集到同一个问题字条目，并保留每次练习明细。
- 重点字库：在“字本”内增加“重点字库”筛选，不新增底部导航；重点字保留入库原因、最近三次均分、稳定性、练习次数和最近练习时间。
- 移出问题字本：矫正完成条件和人工移出规则待补充；MVP 不因单次得分提高自动删除历史记录。

### 4.9 跟踪矫正进度

- 关联重复练习：学生再次练习同一问题字时，将新结果加入该字的矫正序列，并按评测时间排序。
- 比较历次结果：使用相同且可追溯的评价口径比较历次练习；评价基线版本发生变化时，应标明不可直接比较或按待补充规则重新评估。
- 更新矫正状态：矫正状态至少区分待练习、练习中和待确认完成；完成阈值和连续达标次数待补充。
- 保留退步记录：后续练习质量下降时仍保留真实结果，不只展示最佳成绩。
- 有效样本：只有状态为已完成或部分完成、当前单字具有有效总分、目标字一致且评分版本与标准字版本可比的记录，才能进入同一成长曲线和稳定性计算；不确定、失败和已取消结果排除。
- 样本不足：可比练习为一次或两次时，展示“再练 N 次开启成长曲线”，稳定性为 `null`，不得推断趋势或纳入重点字库。
- 成长曲线：从第三次可比练习起，按练习时间展示总分点、五维分数明细和监测门槛；历史记录不因入库或退出而删除。
- 稳定性 POC 口径：取最近三次可比总分，使用样本标准差衡量波动，并对持续下降额外扣分；`stability = round(clamp(100 - 2 × sampleStdDev - 6.5 × max(0, 第一次分数 - 第三次分数), 0, 100))`。绝对低分由“最近三次均分”独立监测；正式公式必须经样本校准后以版本配置替换。
- 重点入库：可比练习不少于三次，且最近三次均分或稳定性低于 `monitorEnterThreshold` 时自动进入重点字库；POC 默认阈值为 `70`。
- 重点退出：最新连续三次可比总分均不低于 `monitorExitThreshold`，且最近三次均分和稳定性均不低于该阈值时自动退出重点状态；POC 默认阈值为 `80`，历史入库记录继续保留。
- 版本变化：评分版本或标准字版本变化时，成长曲线显示断点，旧结果保留但不与新版本共同计算稳定性和重点入库条件。

### 4.10 处理失败与数据安全

- 记录处理状态：评测任务状态固定为 `pending_local`、`uploading`、`analyzing`、`completed`、`partially_completed`、`failed`、`cancelled`，合法迁移、重试检查点和取消语义以 [`../contracts/assessment-task-state-machine.json`](../contracts/assessment-task-state-machine.json) 为准；单字“不确定”和反馈后的“重新评测”分别由结果分类与关联任务表达，不另造任务状态。
- 支持失败恢复：处理失败时保留失败原因和可重试信息；重试不得重复写入问题字本或重复计入矫正进度。
- 保护未成年人数据：练习图片、评测结果和历史记录的采集授权、访问控制、保存期限、删除、更正及模型调用边界待合规评审确认。
- 保留必要审计：学生反馈、重新评测、数据删除和授权变化应可追溯；审计保存期限待补充。
- 私有存储：原图、裁剪图和评测文件必须存入用户隔离的私有云存储，客户端和第三方不得获得长期公开地址。
- 默认留存：工程默认按原图及裁剪图 30 天、结构化记录至用户主动删除设计；该默认值不是合规结论，投产前必须审批。
- 密钥边界：微信小程序不得包含 OCR、大模型或云资源密钥，只能调用完成身份和所有权校验的云函数/BFF。

### 4.11 受控分享

- 分享前确认：生成分享卡前再次要求监护人确认分享内容和范围。
- 最小化内容：分享卡只包含目标字、脱敏评分摘要、问题类别和鼓励性建议，不包含原始图片、单字裁剪图、文件地址、学生真实姓名或内部任务标识。
- 独立撤销：删除分享卡或撤回授权不修改原始练习结果，但应立即阻止后续访问并保留最小审计记录。
- 禁止扩展：MVP 不以分享卡为入口提供公开动态、排行、挑战、积分或用户关系链。

## 7. 其他附件与补充说明

- 原始需求来源：仓库根目录 `hanzi.md`。
- 核心场景来源：`harness/scenarios/core-flows.yaml` 中的 SCN-000 至 SCN-010。
- 客户端与云端：已确定采用微信原生小程序、微信云开发+BFF和独立评测服务；正式研发受 `mobile-v2` 原型门禁控制。
- 原型依赖：需完成登录/授权、学生上传、分析阶段、单字详情、问题字本、重复练习、结果反馈、重新评测、删除和受控分享的可点击原型。
- 评价口径：需由汉字书写教育专家确认错字、待纠偏、五维权重、稳定性、重点入库/退出和矫正完成定义；当前 `70/80` 仅为 POC 默认值。
- 标准资源：需确认标准宋体字库、规范字形、笔画和笔顺数据来源、版本及使用许可证。
- 样本与评测：当前暂无经授权样本，进入模型研发前需建立样本征集授权、脱敏、标注、争议仲裁和评测基线。
- 数据合规：需完成未成年人数据授权、最小化采集、保存期限、删除、更正、访问控制和第三方模型处理边界评审。
- 权限关系：MVP 以学生使用为主，监护人承担图片处理和分享确认；法律身份校验、撤回和查看范围仍需合规确认。
- 非功能指标：识别准确率、分类精确率与召回率、评分一致性、处理时延、可用性、容量和成本目标待样本基线及技术选型后补充。
- 需求优先级：本文件列入 MVP 范围的能力均为首期闭环所需；任何删减应同时检查 SCN-000 至 SCN-010 是否仍可闭环。
