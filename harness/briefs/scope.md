# 当前范围与阶段边界

## 本阶段包含

- 保留原始产品说明并建立可追溯的产品摘要。
- 建立技术无关的核心业务验收场景。
- 定义未来 fixture 与验证结果的治理规则。
- 提供原型评审和技术选型记录模板。
- 维护已批准的 ArkUI-X 多端客户端技术决策和能力验证清单。
- 提供仓库结构校验，防止研发工程被提前创建。

## 本阶段明确不包含

- UI 页面、交互原型或视觉设计实现。
- 前端、后端、移动端、模型服务、数据服务等源码目录。
- 正式客户端的 `package.json`、依赖锁文件、构建器和运行时配置；隔离的能力 PoC 需在门禁记录中单独管理。
- OCR、多模态模型、图像切分、评分或 diff 算法实现。
- 数据库结构、API 契约、部署方案或云资源配置。
- 真实或合成练字样例、标准字库及模型评测数据集。
- 未经确认的评分阈值、准确率、延迟或容量指标。

## 进入研发工程的准入条件

以下条件应全部满足：

1. 核心用户流程和关键异常流程已在原型中呈现。
2. 原型评审结论为通过，未决问题有责任人与处理计划。
3. 客户端技术选型已批准；服务端、识别/评估能力和部署方式在对应工程启动前完成选型。
4. 未成年人数据与图片处理的隐私、安全和授权边界得到确认。
5. ArkUI-X 三端关键能力验证通过。
6. 仓库目录方案经确认，并同步更新 `manifest.yaml` 与 `bin/validate`。
