# 原型确认阶段范围与边界

## 当前阶段目标

在微信小程序正式研发前完成一轮功能原型确认，使产品、设计、客户端、后端/算法、测试和隐私负责人能对同一套成功、异常、离线和恢复流程进行书面审批。

## 当前允许交付

- 更新 MVP、技术决策、评测流水线、业务场景和隐私门禁。
- 输出 `mobile-v2` 页面清单、导航图、交互说明、状态矩阵、文案样例和需求追踪表。
- 构建仅用于评审的可点击高保真原型，并进行手机/PAD 响应式和核心交互验证。
- 读取冻结的 `client/`，盘点待迁移 API 契约、Schema、状态机和合成 fixture。
- 使用公开文档验证微信、OCR 与模型接口可行性；不得创建生产云资源。

## 当前禁止交付

- 创建 `miniprogram/`、正式云函数、BFF、智能评测服务或模型工程目录。
- 继续开发、发布或扩展 ArkUI-X `client/`。
- 调用真实学生图片、部署生产 OCR/模型、创建生产数据库或配置真实密钥。
- 删除旧 `client/`；删除动作必须等新原型批准且公共契约迁移验证通过。
- 将原型中的模拟结果宣称为真实识别准确率、处理时延或生产评分。

## 正式研发准入条件

以下条件必须全部满足：

1. 可点击高保真原型覆盖完整成功路径和主要异常路径。
2. 页面清单、状态矩阵、文案、响应式规则和需求追踪表完整。
3. 产品、交互视觉、客户端、后端/算法、测试和隐私负责人完成书面评审。
4. 原型评审记录状态为 `approved`，所有阻塞项关闭。
5. 微信小程序技术决策与评测流水线 ADR 均为 `accepted`。
6. 未成年人数据处理可继续保持发布门禁，但必须明确研发阶段可使用的数据范围。
7. `manifest.yaml` 与 `bin/validate` 已切换到研发阶段并明确允许创建的正式目录。

## 变更控制

通过后的 `mobile-v2` 是 V1 体验基线。新增页面、改变主流程、改变结果分类或修改未成年人授权/分享行为时，必须登记变更影响并重新评审相关页面；纯文案错别字和不改变行为的视觉微调可在评审记录中追加说明。
