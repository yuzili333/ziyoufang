# 实现验证范围与阶段边界

## 本阶段包含

- 保留原始产品说明并建立可追溯的产品摘要。
- 建立技术无关的核心业务验收场景。
- 定义未来 fixture 与验证结果的治理规则。
- 提供原型评审和技术选型记录模板。
- 维护已接受的 ArkUI-X 多端客户端技术决策和能力验证清单。
- 维护已批准的 mobile-v1 原型与评审记录。
- 创建并验证 ArkUI-X 正式客户端工程、平台宿主和公共接口骨架。
- 提供仓库结构校验，防止未完成选型的服务端、模型或数据工程被提前创建。

## 本阶段明确不包含

- 已确认原型以外的完整业务页面和生产功能实现。
- 后端、模型服务、数据服务等源码目录。
- 服务端、模型服务、数据服务等尚未完成选型的正式研发工程。
- OCR、多模态模型、图像切分、评分或 diff 算法实现。
- 生产数据库结构、服务端 API 实现、部署方案或云资源配置。
- 真实或合成练字样例、标准字库及模型评测数据集。
- 未经确认的评分阈值、准确率、延迟或容量指标。

## 进入发布研发阶段的准入条件

以下条件应全部满足：

1. 核心用户流程和关键异常流程已在 mobile-v1 原型中呈现。
2. 原型评审已经批准，客户端技术决策已经接受。
3. 服务端、识别/评估能力和部署方式在对应工程启动前完成选型。
4. 未成年人数据与图片处理的隐私、安全和授权边界得到确认。
5. ArkUI-X 三端构建、运行和关键能力验证通过。
6. 仓库目录方案经确认，并同步更新 `manifest.yaml` 与 `bin/validate`。
