# E02/E04 手机图片接入基础验证

## 结论

- 日期：2026-08-11
- 状态：`verified-local-synthetic-jpeg-png`
- 范围：微信小程序选图格式保留、评测服务格式探测、JPEG/PNG RGBA 解码、EXIF 方向和资源上限。
- 结论：手机常用 JPEG 与产品允许的 PNG 已进入同一像素评测入口，且 JPEG 合成照片通过完整质量检查、4×4 切格和 16 字结果流水线。该记录不代表 HEIF、真实微信设备照片或生产负载已经验收。

## 已实现边界

1. 小程序通过 `wx.getImageInfo` 获取图片类型，只接受 JPG/JPEG/PNG，并让云对象扩展名与已识别类型一致，不再把 PNG 内容固定命名为 `.jpg`。
2. 服务端不信任对象扩展名，依据 PNG/JPEG 文件签名字节选择解码器；伪装扩展名不能绕过格式检查。
3. PNG 保持既有有界 RGBA 解码；JPEG 使用锁定版本 `jpeg-js@0.4.4`，关闭宽容解码并限制分辨率和内存。
4. 统一入口限制编码文件不超过 15MB、像素不超过 2000 万；空文件、损坏文件、未知格式和超限文件返回稳定错误码。
5. JPEG 在质量检查和切格前读取 EXIF Orientation 1–8，并按方向翻转或旋转 RGBA 像素。
6. 不可解码的用户输入统一形成 `retryable=false`，客户端给出重新拍摄/重新选择的针对性提示，不诱导重复提交同一坏文件。

## 自动验证

- 由批准的 1600×1600 合成 PNG 编码生成 JPEG，经过统一解码后完成 4×4 切格和 16 字评测。
- 使用带 Orientation=6 的非方形 JPEG 验证宽高交换发生在质量检查之前。
- 覆盖 PNG/JPEG 魔数探测、后缀伪装、空输入、WebP/未知格式、截断 JPEG、15MB 上限和稳定错误码。
- 小程序静态流测试验证在线上传与离线恢复均使用保存的 `mediaFormat` 选择扩展名。

## 仍受门禁约束

- HEIF/HEIC、WebP、广色域 ICC、CMYK JPEG 和超高分辨率降采样尚未进入支持范围；客户端会拒绝非 JPG/JPEG/PNG。
- `jpeg-js` 是同步纯 JavaScript 基础实现；真实负载测试后须决定是否迁移到隔离工作线程或经过部署验证的原生解码服务。
- 尚无微信开发者工具或 iOS、Android、HarmonyOS 真机照片，因此类型字段、EXIF 样本和相册兼容性仍需 E10 验收。
- 透视、反光、阴影和通用方格切分仍属于真实算法 POC，不因 JPEG 能解码而视为完成。
