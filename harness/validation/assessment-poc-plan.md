# 智能书写评测 POC 执行与验收计划

## 状态与边界

- 状态：`blocked-by-poc-input-approval`
- 技术基线：OCR + 确定性图像算法 + 多模态模型解释。
- 默认候选：腾讯云 OCR 与腾讯混元兼容接口；两者都必须通过 Provider 接口，可在同一评测集替换比较。
- 数据边界：只允许合成、脱敏或具有可核验证明的授权样本；隐私评审批准前禁止真实学生数据进入 POC 环境。
- 输出边界：POC 用于形成基线、选择供应商和校准阈值，不得作为教育评价标准或产品准确率宣传。
- 机器输入计划：[`poc-evaluation-plan.json`](./poc-evaluation-plan.json)。当前只登记了哈希校验通过的 `multi-grid-v1` 合成冒烟集，尚无获批验证集或指标目标。
- 就绪检查：`node harness/bin/check-poc-inputs.mjs`；原型已批准，但只有该命令以 `--require-ready` 成功后才可启动真实 Provider POC。

## 解锁条件

1. `prototype_review.status == approved`。
2. 产品、算法和测试共同批准评测集清单、标注口径、指标目标和误差处理方式。
3. 每个非合成样本具备来源、授权范围、到期时间和可删除证明。
4. 标准宋体文件的商用、服务器渲染和测试再分发许可已确认。
5. OCR/模型凭据只注入服务端受控环境，不写入仓库、客户端、fixture 或日志。
6. [`poc-evaluation-plan.json`](./poc-evaluation-plan.json) 状态为 `approved`，所有指标目标由产品、后端/算法和测试签署，且固定文件哈希无漂移。

## POC 阶段

| 阶段 | 主要工作 | 必须产物 | 退出条件 |
| --- | --- | --- | --- |
| P0 契约基线 | 固定任务状态、结果 Schema、问题代码、Provider 接口和版本字段 | 契约测试、固定输入输出、版本清单 | 现有 V2 fixture 全部通过且无供应商字段泄漏到业务层 |
| P1 图片与切格 | EXIF、旋转、亮度、模糊、反光、透视、方格检测和单字裁剪 | 每页质量结果、方格 polygon、失败原因、可视化抽检证据 | 清晰/模糊/残缺样例行为一致，切格指标可计算 |
| P2 OCR 与对齐 | 整页 OCR、低置信单格二次 OCR、目标字对齐、错漏多字 | OCR 原始候选、归一化置信度、二次调用原因、对齐结果 | 能区分稳定、冲突和不确定；模型不能改写 OCR 结论 |
| P3 字形与评分 | 标准字渲染、归一化、轮廓/骨架/重心/占格/结构特征和五维评分 | 特征向量、问题代码、差异图、评分版本、专家抽检表 | 前四维可追溯到确定性证据；笔顺不从静态图伪推断 |
| P4 模型建议 | 批量问题字、结构化提示、JSON Schema 校验、模板降级 | 提示词版本、合规输入摘要、模型输出、非法 JSON/超时证据 | 最多3条建议且与问题代码一致；失败不影响确定性结果 |
| P5 端到端 | 幂等、缓存、有界重试、部分完成、取消、成本和 P95 时延 | 汇总报告、失败明细、成本拆分、供应商请求 ID 脱敏记录 | 所有批准指标均有测量值；未达标项有归因和处置决定 |

## 评测集清单

评测集必须按以下维度分层并记录数量；未填写和批准前不得报告通过：

- 页面：单行/多行、规则方格/轻微变形、不同纸张与墨色。
- 图像：0/90/180/270 度、透视、阴影、反光、模糊、残缺、过暗/过曝。
- 字符：常用独体字、左右/上下/包围结构、易混淆字、漏字、多字和非目标字。
- 书写结果：正常、错字、待纠偏、不确定、失败。
- 年龄/书写阶段：只有在授权与合规允许时分层；不得从姓名、微信身份或无关属性推断。
- 版本：数据集 ID、标注规范版本、标准字版本、OCR/算法/模型/提示词版本必须固定。

每个样本至少记录 `sampleId`、来源类型、授权证明引用、图片质量标签、目标文本、方格标注、字符真值、可用评价标签和排除原因。原图不得进入 Git；仓库只保存无敏感信息的清单与摘要。

## 指标定义

| 指标 | 计算口径 | 主要切片 |
| --- | --- | --- |
| 方格切分召回率 | 匹配到真值方格的数量 / 真值方格总数；IoU 阈值由评测口径批准 | 图片质量、页面结构 |
| 单字 OCR 准确率 | 正确首选字符 / 可识别真值字符；另报 Top-K 和不确定覆盖 | 字形结构、图像质量、二次 OCR |
| 错字精确率/召回率 | 以批准的双 OCR＋对齐口径计算，单列不确定 | 易混淆字、错漏多字 |
| 纠偏人工一致性 | 算法问题代码与两名以上书写专家标注的一致程度 | 五维、结构类型、分数区间 |
| 建议可执行性 | 盲评“证据一致、低龄可懂、可操作、无越界结论” | 问题代码、模型/模板降级 |
| 稳定性合理性 | 同字三次及以上序列与专家对波动/下降的判断一致性 | 得分波动、持续下降、版本断点 |
| P95 时延 | 从服务端接受任务到结果可读；同时分解各阶段 | 字数、缓存命中、供应商 |
| 单次成本 | OCR、模型、计算、存储和出网的加总 | 页数、单字数、问题字比例 |

目标值必须写入独立、经批准的 POC 目标记录；本计划不预设产品准确率。POC 高/低 OCR 阈值 `0.90/0.60` 和重点监测 `70/80` 仅作为待校准初值。

## 固定回归场景

1. 清晰多方格页面完整成功。
2. 模糊或裁切不完整页面终止并给出重拍建议。
3. 单格 OCR 冲突返回不确定，不写入字本。
4. 两次稳定非目标 OCR 且对齐明确时形成错字。
5. 内容正确但确定性特征异常时形成待纠偏与五维证据。
6. 单格失败返回 `partially_completed`，其他字符仍可用。
7. 模型超时、限流和非法 JSON 降级为规则建议。
8. 重试沿用同一幂等键，不重复任务、字本或成长点。
9. 少于三次稳定性为空；第三次起形成成长曲线和重点监测判定。
10. 评分/字形版本变化产生断点，不跨版本计算稳定性。

## POC 报告最小内容

- 运行 ID、时间、环境、代码提交、数据集和标注版本。
- OCR、算法、标准字、模型、提示词和阈值版本。
- 每项指标的目标、测量值、置信区间或样本量、通过状态和失败切片。
- 超时、重试、缓存命中、部分完成、降级和成本明细。
- 所有误分类样例的匿名引用及处置决定。
- 产品、算法、测试和隐私责任人的结论；未批准目标或未完成数据证明时结果只能是 `inconclusive`。
