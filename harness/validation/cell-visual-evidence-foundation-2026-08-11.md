# E04 单字像素证据基础验证

## 结论

- 日期：2026-08-11
- 状态：`verified-local-pixel-synthetic`
- 范围：方格像素裁剪、PNG 编码、OCR 批次输入、模型问题字视觉证据和降级边界。
- 结论：切格结果已不再只是坐标。流水线会从解码后的真实页图裁剪每个目标方格，形成受限 PNG，传给 OCR；问题字再携带同一裁剪图、OCR 候选、确定性特征和经批准的标准字引用进入建议层。视觉 Base64 只存在于当前处理过程，不进入结果、仓库或遥测。结论仅由合成像素和模拟 Provider 证明。

## 已实现链路

1. 对每个 `pixelBounds` 执行边界校验；越界、反向或空区域以稳定错误码终止，不进行越界读取。
2. 默认向内裁去 2% 方格边缘，减少朱红网格线进入 OCR，同时保留结果中的原始四点 `polygon` 供客户端定位。
3. 单字图按比例缩放到最长边不超过 1024px、像素不超过 1,048,576，并使用 8-bit RGBA、非隔行 PNG 编码。
4. 单个 PNG 不超过 2MB，同一任务临时单字 PNG 总量不超过 24MB；最多处理 64 格。
5. OCR 输入包含 `cellId/index`、裸 PNG Base64、裁剪宽高和坐标元数据，并按最多 32 格分批。
6. 建议层按最多 8 字分批；每项包含目标字、裁剪图 Data URL、OCR 候选、原有问题代码和有限数字特征。
7. 视觉模型声明 `requiresVisualEvidence=true` 后必须由 `GlyphProvider` 返回版本一致的标准字 Data URL；标准字缺失或渲染失败时，组合 Provider 降级为规则模板，不让已完成的确定性结果失败。
8. 最终 `CharacterResult` 只保留坐标、候选、分数、问题和版本，不包含 `imageBase64`、图片 Data URL 或临时裁剪对象。

## 自动验证

- 从批准 4×4 PNG 的第一个方格裁剪出 344×344 RGBA，并经新编码器/既有解码器逐字节往返一致。
- 对整页裁剪验证自动缩放为 1024×1024；覆盖负坐标、空边界和视觉证据格式。
- 记录型 OCR Provider 证明 16 个单格均收到真实 PNG Base64；40 格合成任务证明批次严格为 `32 + 8`。
- 记录型视觉建议 Provider 证明问题字收到裁剪图、标准字图、目标字、OCR 候选和确定性特征。
- 结果序列化检查证明不存在 `data:image/` 或 `imageBase64`。
- 缺少标准字 Provider 时，混元组合适配层降级到版本化规则建议，任务仍形成部分完成结果。

## 尚未完成

- 当前合成 OCR 仍提供受控的双次候选和评分证据；腾讯云原始整页/单格响应尚需通过真实 POC 完成阅读顺序对齐、低置信二次调用和确定性评分适配。
- 标准宋体许可证尚未批准，因此仓库没有正式 `GlyphProvider` 字体文件或生产字形渲染实现；测试只使用明确标记的 1px 合成引用验证接口。
- 当前裁剪使用轴对齐外接矩形；倾斜四边形透视展开、反光/阴影处理和笔画级差异图仍属于真实算法 POC。
- PNG 编码和双线性缩放运行在当前 Node 进程；真实并发负载后须评估工作线程、任务队列和内存水位。
