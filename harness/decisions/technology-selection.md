# ADR-001：微信小程序客户端技术选型

## 决策信息

- 记录编号：`ADR-001`
- 初始日期：2026-08-07
- 最近更新：2026-08-11
- 状态：`accepted`
- 被替代决策：ArkUI-X 6.0.0 + ArkTS 三端独立客户端
- 决策范围：MVP 学生端载体、云端能力边界、依赖策略和旧工程处置
- 决策依据：综合研发、投产和获客成本后，产品方明确选择微信小程序
- 当前门禁：技术决策与 `mobile-v2` 六方原型评审均已批准，正式研发进入 `implementation-validation`；真实 Provider、真实学生数据和发布仍受后续门禁约束

## 决策摘要

字有方 MVP 采用 **微信原生小程序 TypeScript + 微信云开发 + 独立智能评测服务**。小程序承担拍照/相册选择、离线待提交、任务进度、单字结果浏览、字形对比、问题字本和受控分享；云开发承担微信身份、私有文件、云数据库、云函数/BFF 和任务同步；独立评测服务承担图片质量、方格切分、OCR、差异计算、评分和大模型建议。

客户端不得直接调用 OCR 或大模型，不得包含供应商密钥。现有 `client/` ArkUI-X 工程立即冻结；只有在新原型门禁通过、公共契约和合成 fixture 完成迁移后才允许删除，不维护双技术栈。

## 方案比较

| 方案 | 优势 | 主要成本与风险 | 结论 |
| --- | --- | --- | --- |
| 微信原生小程序 | 免安装；微信登录、扫码和分享链路成熟；TypeScript 团队上手快；拍照、相册、云开发和审核链路集中 | 受微信基础库、宿主、配额和审核规则约束；长期离线、复杂绘制及 PAD 体验需专项验证 | **采用** |
| ArkUI-X | HarmonyOS、Android、iOS 共用 ArkTS 业务代码，可形成独立安装包 | 相机桥接、三端签名/发布和生态维护成本高，MVP 投产链路重 | 被本决策替代 |
| Flutter | Android/iOS 生态和自绘能力成熟 | HarmonyOS 依赖社区分支，需承担分支、插件和多商店发布成本 | 不采用 |
| React Native | TypeScript/React 人才生态成熟 | HarmonyOS 依赖适配层，原生模块兼容和多端发布仍需逐项维护 | 不采用 |

## 已确认约束

- 技术栈：微信原生 WXML/WXSS/TypeScript，不引入跨端 UI 框架、第三方路由或全局状态框架。
- 基础库：最低版本暂定 `2.32.3`；正式值在真机兼容验证后锁定。
- 终端覆盖：在 iOS、Android、HarmonyOS 微信客户端中验收；这表示微信宿主可用性，不宣称生成三端独立应用。
- PAD：按窗口宽度响应，不按设备型号判断；MVP 只确认双栏信息架构，不交付 PAD 专属交互。
- 数据架构：云端结构化数据为联网后的事实源；本地只保存设置、缓存和未提交任务，恢复网络后按幂等键同步。
- 身份：以微信身份作为登录入口；未完成隐私授权和监护人确认不得上传或持久化未成年人练字图片。
- 分享：只允许监护人再次确认后生成脱敏结果卡；不分享原始图片，不提供排行、积分或挑战。
- 范围排除：教师复核、人工审核及周报、月报、季度报、年报均不进入 MVP。

## 客户端与云端边界

### 小程序

- 使用 `wx.chooseMedia` 或相机组件获取图片，完成格式、体积和本地空间检查。
- 断网时通过文件系统保存待提交图片和任务元数据；不得静默删除未提交任务。
- 使用云函数创建任务、上传私有文件、查询状态、取消、反馈、删除和生成脱敏分享卡。
- 只展示服务端返回的结构化边界框、差异标注、五维评分、成长曲线、重点字库状态、问题代码和建议，不在端侧运行 OCR、OpenCV、稳定性计算或模型。

### 云开发 BFF

- 校验 `openid`、监护人授权、文件所有权、幂等键和任务状态。
- 维护私有云存储、云数据库、任务状态和短期服务端访问凭证。
- 幂等维护同一字的可比练习序列、稳定性、成长曲线和重点字库状态。
- 通过稳定 HTTPS 契约调用独立评测服务；供应商密钥只保存在服务端密钥管理中。
- 对分享、反馈、删除和授权变化保留最小必要审计。

### 智能评测服务

- 图片质量检查、旋转/透视校正、练字本和方格检测、单字切分。
- 整页 OCR、冲突单格二次 OCR、目标文本对齐和不确定性处理。
- 标准宋体参考字渲染、确定性差异特征、版本化评分和问题代码。
- 仅对问题字或不确定字调用多模态模型解释证据和生成建议；模型不得覆盖 OCR、分类或评分。

详细流水线与供应商适配策略见 [`assessment-pipeline.md`](./assessment-pipeline.md)。

## 依赖与平台策略

- 小程序依赖使用 npm 且锁定确切版本；能用官方 API 时不引入第三方包。
- 云开发资源、OCR、模型、对象存储和告警必须区分开发、预发布、生产环境。
- OCR 与模型分别由 `OcrProvider`、`VisionCorrectionProvider` 隔离；业务不得依赖腾讯云响应结构。
- 腾讯云作为首期默认供应商，但生产启用必须通过授权样本评测和成本门禁。
- 供应商端点、模型名、密钥、超时、配额和熔断参数通过环境配置注入。

## 旧工程处置

1. 新原型批准前，`client/` 保留但冻结，只允许读取和迁移通用契约/fixture，不继续开发。
2. 原型批准后，将 API 契约、任务状态、结果 Schema、合成图片和断言迁入新工程。
3. 迁移验证通过后删除 `client/`，并在同一变更中移除 ArkUI-X 专属脚本和依赖。
4. 删除前保留本 ADR、能力验证记录和 Git 历史作为决策证据，不另建归档工程。

## 风险与退出策略

- 微信宿主风险：使用最低基础库和三端真机矩阵验证；关键 API 不可用时降级为相册选择或明确阻断，不静默失败。
- 本地容量风险：对未提交文件做容量预检和可见清理；已提交缓存可按 LRU 清理，未提交文件须经用户确认。
- 平台锁定风险：业务契约、状态机和评测服务保持平台无关；若微信规则阻断核心闭环，可依据同一契约重新评估独立客户端。
- OCR 风险：腾讯云通用手写体 OCR 已属于旧版本服务，只作为 POC 候选，生产前必须完成同样本基准测试。
- 模型迁移风险：混元能力正在向 TokenHub 迁移，端点和模型不得硬编码。
- 合规风险：隐私、监护人授权、第三方处理和字形许可证未批准前，禁止生产投放。
